# Fast Track 2040 scenario

Fast Track starts from the same common-measures BAU GTFS and then adds U9, the U4 extension and two Nordring services associated with infrastructure that could be accelerated for a hypothetical Munich Olympic Games. The four-track Daglfing–Johanneskirchen measure is only an enabling condition; physical rail capacity is not represented. Existing S8 service remains unchanged.

The production config `config_fast_track.xml` references the rebuilt files in `input_transit/` and the scenario-specific `population_2040_fast_track.xml`. The latter is reproducibly derived from the unchanged common `population_2040.xml` by `CreateFastTrackVillagePopulation2040`: existing persons are relocated to Olympic Village and Media Village demand coordinates, without creating agents or changing times, modes, plan structures or person attributes. The BAU population remains unchanged.

The village representation is deliberately limited to relocated `home` and `work` activities on existing car links. It does not create buildings or roads and does not yet distinguish permanent residents, Games-time accommodation, media employment or visitors. See the [population methodology](../../docs/methodology/population_2040.md) and the [authoritative transit-input methodology](../../docs/gtfs2040/matsim_2040_transit_inputs.md).

Twelve Fast Track Mobility Hubs are implemented as a separate analytical assumption: four large, four medium and four small hubs. The final schedule post-processor reads the versioned specification and changes exactly 790 existing directed cross-stop transfer times, with class reductions of 20%, 15% and 10% and a 60-second floor. It retains all 95,912 transfer relations and excludes 103 self-relations. The step is Fast-Track-only and passed focused tests, full input readback and a two-person iteration-zero smoke test. Shared mobility, parking, physical construction and public-space quality are not represented. See the [Mobility Hub methodology](../../docs/methodology/mobility_hubs_fast_track.md).
